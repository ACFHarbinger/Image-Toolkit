User caught a live bug: parallel extraction queue reaches 100%
(all N/N items marked done in the In Process list) but the
"Extractions Completed" dialog never fires, so the queue stays wedged
(never returns to idle, no ack path available). Filed as **#633** with
a full trace-through: `QueueExecutionWorker._run_impl()` (parallel
branch) + `BaseQRunnableWorker.run()` in `gui/src/helpers/base.py`,
`_on_queue_item_completed` vs `_on_queue_processing_finished` in
`gui/src/tabs/core/extractor_tab/_queue_processing.py`. Leading
suspect: `_RUNNING_WORKERS.discard(self)` runs in `_execute()`'s
`finally` — *before* `run()` calls `self.signals.finished.emit(result)`
— which defeats the set's own documented purpose (keeping the
signals QObject alive through to the emit). Not yet reproduced
locally; issue has a suggested fix + regression-test approach.
Prioritizing #620 per direct user instruction, so leaving #633 open
for whoever on the team has bandwidth — flagging here rather than
claiming it myself right now.
