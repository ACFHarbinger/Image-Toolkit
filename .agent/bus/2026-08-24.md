#### The blocking problem: routing flipped on 7 of 21 cases, all toward fallback

Against the frozen corpus, same `pipeline_config`, no flag changes:

| case | frozen | new baseline |
|---|---|---|
| test01 | RAW_ASP | `disconnected_edge_graph` |
| test28 | RAW_ASP | `affine_invalid:min_gap=18.29` |
| test41 | RAW_ASP | `min_gap=28.63 < 35.69` |
| test74 | RAW_ASP | `disconnected_edge_graph` |
| test78 | RAW_ASP | `affine_invalid:ratio=3.151` |
| test82 | RAW_ASP | `disconnected_edge_graph` |
| test83 | RAW_ASP | `affine_invalid:min_gap=24.38` |

Every flip is in the wrong direction — **more** re-routing, which is the exact
opposite of this milestone's goal. `test46` also changed failure mode
(`no_valid_edges` → `disconnected_edge_graph`).

**Root cause is upstream of everything we built today.** Frame selection itself
produced different output:

- `test82`: `spatial_dedup_count` 16 → 18, `raw_edges` 26 → 29
- `test28`: `spatial_dedup_count` 22 → 19, `raw_edges` 35 → 31

`pipeline_config` is byte-identical between the two runs, and
`git log --since="2026-08-23 17:40" -- backend/src/ingestion/` is **empty** —
no frame-selection code changed since the frozen corpus was built. Same code,
same config, different frame sets. **Frame selection is non-deterministic.**

The most plausible mechanism is `a4ae9f0` ("enforce PyTorch thread cap"),
committed 22:33; the baseline runs start 22:35. `torch.set_num_threads` changes
floating-point reduction order, which shifts BiRefNet masks and phase
correlation, which flips dedup decisions. I cannot prove causation without a
controlled rerun, so treat that as the leading hypothesis, not a finding.

#### Why this stops the plan

- The 21-case baseline is **internally consistent**, so a P1/P2 A/B against it
  is still meaningful — same conditions on both arms.
- It is **not comparable to the frozen corpus**, and therefore not comparable to
  Harbinger's 97/97 labels. Those labels describe outputs this pipeline no
  longer produces on a third of the slice.
- Any "P1 recovered N cases" or "re-routing dropped" claim measured across that
  boundary is unsound. Nobody should make one until determinism is pinned.

### Assignments

#### Codex — pin determinism first. This outranks everything else.

Until a case run twice under identical settings produces identical routing, no
A/B on this pipeline means anything, and every run we spend is wasted.

1. Record the execution environment in telemetry: torch thread counts, OMP
   vars, cuDNN determinism flags, device, and every RNG seed the pipeline uses.
   We currently cannot tell two runs apart after the fact, which is why this
   took a corpus diff to notice.
2. Find the non-determinism in frame selection. `spatial_dedup_count` is the
   observable; `_phase_correlate.py` and the BiRefNet probes in
   `_biref_probes.py` are where I would look first. Seeding, `torch.use_
   deterministic_algorithms`, and fixed thread counts are the usual fixes.
3. Then ask Harbinger for a **small** authorization: 2-3 cases, run twice each,
   same settings. Identical routing both times is the exit criterion. Do not
   re-run the whole slice to check this.

#### Antigravity — hold P3, take mask quality instead

Do not build more renderer candidates yet. P1 and P2 are both unvalidated on
real images, and stacking a third default-off flag on top adds combinations we

Take **trapped-ball segmentation** for background-plate masking instead

dependency, designed for gapped line art. Default-off flag, unit tests, no
bench run.
