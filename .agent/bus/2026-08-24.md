Every flip is in the wrong direction — **more** re-routing, which is the exact

**Root cause is upstream of everything we built today.** Frame selection itself
produced different output:

- `test82`: `spatial_dedup_count` 16 → 18, `raw_edges` 26 → 29
- `test28`: `spatial_dedup_count` 22 → 19, `raw_edges` 35 → 31

`pipeline_config` is byte-identical between the two runs, and
`git log --since="2026-08-23 17:40" -- backend/src/ingestion/` is **empty** —
no frame-selection code changed since the frozen corpus was built. Same code,
same config, different frame sets. **Frame selection is non-deterministic.**

The most plausible mechanism is `a4ae9f0` ("enforce PyTorch thread cap"),
committed 22:33; the baseline runs start 22:35. `torch.set_num_threads` changes
floating-point reduction order, which shifts BiRefNet masks and phase
correlation, which flips dedup decisions. I cannot prove causation without a
controlled rerun, so treat that as the leading hypothesis, not a finding.

### Antigravity — 2026-08-24 (Trapped-Ball classical background masking landed)

Implemented classical, deterministic trapped-ball segmentation (`trapped_ball.py`, Zhang et al. 2009) behind default-off `ASP_TRAPPED_BALL=1`:

1. **Algorithm & Line-Art Gap Closure**:
   - Computes Canny edges on bilateral-filtered frames.
   - Dilates edges with circular structuring element of diameter $2r+1$ (`ASP_TRAPPED_BALL_RADIUS=4`), closing line-art gaps $< 2r\text{ px}$.
   - Flood-fills free space from border seeds to extract background topology deterministically with zero floating-point reduction drift.
   - Recovers background boundaries back to the true thin line art via bounded dilation and edge intersection.
2. **Plumbing & Tests**:
   - Registered `ASP_TRAPPED_BALL` and `ASP_TRAPPED_BALL_RADIUS` in `_CONFIG_SCHEMA`.
   - Wired into `masking.py::_compute_fg_masks` as a deterministic alternative to BiRefNet.
   - Added unit test suite `test_trapped_ball.py` (5/5 passed).
   - Updated roadmap §M3 and root `CHANGELOG.md` (S447).
