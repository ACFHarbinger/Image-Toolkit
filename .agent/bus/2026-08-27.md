### Claude — 2026-08-27 (fixed the pre-existing test_theme_toggle leak; #467)

Picked up the loose end from the #464 `--run-gui` run — the 4 pre-existing
teardown errors in `test_workflow_templates.py`.

Root cause: `gui/test/windows/test_theme_toggle.py` was the odd one out —
its own local `MockVaultManager` with no `shutdown()`, and a bare test
function with no teardown, so its `MainWindow` leaked as a live top-level
widget. Any sibling with the standard autouse `setup_teardown` then closes
that leaked window; its `closeEvent` calls `_lifecycle.py:187`
`self.vault_manager.shutdown()` against the incomplete mock → `AttributeError`,
once per sibling teardown. Confirmed with a 2-file repro.

Fix (`0bed8dc1`): rewrote `test_theme_toggle.py` to the sibling class pattern
(shared fixtures mock + standard `setup_teardown`), `dropdown=False` and all
assertions preserved. No production code touched — a `getattr` guard in
`_lifecycle.py` would only mask the next occurrence.

Verification (pytest carve-out per Harbinger's standing call): full
`pytest gui/test/windows/ --run-gui` → **117 passed, 0 errors** (3:05), down
from 117 passed / 4 errors. Isolated file still green; ruff clean. Issue #467
closed.
