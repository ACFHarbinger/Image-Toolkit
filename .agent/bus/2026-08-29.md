### Agy — 2026-08-29 (piecewise-P1 implementation-surface audit)

Completed the static analysis and implementation-surface audit for Option A (piecewise per-phase P1):
- **Input assumptions (`_plate_compositor.py`):** `cv2.connectedComponents(union_fg)` cleanly isolates phase-local character poses without cross-phase pollution; `_apply_joint_gain_solve` solves an $N_{\text{span}} \times N_{\text{span}}$ system independently per span. Outside each span's vertical coverage, `composite_plate_single_pose` falls back to `canvas`. `warped_list`, `warped_bg`, and `warped_valid` must be sliced synchronously `[s:e+1]`.
- **Injection point (`composite.py`):** The piecewise multi-phase candidate sits immediately after single-phase P1 and before the multi-phase skip branch (`c3931b93`). If `ASP_PLATE_MULTIPHASE=1` is active and guards pass, it executes and returns; otherwise, control cleanly falls through to the existing skip branch and legacy compositor.
- **`claimed` ownership map:** `claimed >= 0` accurately isolates hero foreground cels per phase. However, because `claimed` marks both valid background plate and unpopulated fallback canvas as `-1`, plate validity / bounding bands must be surfaced (e.g. via `plate_valid` or affine $ty$ span bounds) for plate-to-plate boundary blending. Local `claimed` frame indices must be remapped to global indices.
- **`phase_spans` / `phase_ids` plumbing:** `phase_ids` is already computed post-spatial-dedup in `run_stage.py` and passed to `_composite_foreground`. All required spatial, mask, and frame data are already in local scope. Zero parameter threading from outer callers is needed; only `phase_spans` helper needs importing.
- **Memory warning & formula (§7.2):** Warning should be emitted in `_composite_foreground` before the per-span loop. Derived formula: $\text{Estimated Peak RSS (GiB)} = 2.0 + 3.0 \times n_{\text{phases}}$, matching the 5.01 GiB single-plate sweep anchor ($n=1$) and predicting 11.0 GiB for 3 phases.
