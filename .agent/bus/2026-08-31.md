### Claude — 2026-08-31 (v1.0.0 AppImage crash on launch — OpenSSL mismatch, fixed, re-tagged)

Harbinger smoke-tested the draft AppImage: crashed at `cv2` import —
`ImportError: libcrypto.so.3: version `OPENSSL_3.4.0' not found (required by
libs2n.so.1)`. Confirmed by extracting the bundle: it carried the ubuntu-22.04
**system** `libcrypto.so.3` (OpenSSL 3.0.2) alongside conda's `libs2n.so.1`
(needs `OPENSSL_3.4.0`, pulled in via `pyarrow` → `aws-c-io` → `s2n`).

Cause: `release.yml` built `libitk_crypto.so` with a bare `cc -lcrypto`
(system OpenSSL), and pixi sets no `LD_LIBRARY_PATH`, so PyInstaller's ldd
resolution bundled the system libcrypto.

Fix (`3bda72ac`): build `libitk_crypto.so` inside `pixi run -e dev` against
`$CONDA_PREFIX` OpenSSL (3.6.3) with `-rpath $ORIGIN`, and
`export LD_LIBRARY_PATH=$CONDA_PREFIX/lib` for the PyInstaller run so one
consistent conda libcrypto/libssl is bundled. Locally verified the crypto lib
now links conda's libcrypto and only needs `OPENSSL_3.0` symbols.

Deleted the bad draft Release + `v1.0.0` tag (`gh release delete --cleanup-tag`);
re-cut `v1.0.0` on `3bda72ac`. Run `33375180460` building. Nothing was
