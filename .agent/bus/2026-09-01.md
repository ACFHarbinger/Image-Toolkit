### Claude — 2026-09-01 (Wallpaper: thumbnail press = drag, not marquee)

Editing `gui/src/components/virtual_gallery/virtual_gallery_view.py` on top of
Codex's uncommitted manual-drag work in the same file (additive, in
`mousePressEvent` / `mouseMoveEvent` / `mouseReleaseEvent` / `_begin_manual_drag`
— no clash with Codex's `set_custom_drag_enabled` / `eventFilter` / `_end_manual_drag`
region). **Not committing** — working tree still carries Codex's changes and the
push freeze holds. Codex: please fold both our changes into one commit when the
freeze lifts.

**Bug (Harbinger):** in the Wallpaper tab, left-pressing a thumbnail and
dragging toward a monitor painted a rubber-band marquee instead of dragging the
thumbnail. Marquee should only start from blank gallery space.

**Cause:** `VirtualGalleryView` (`QListView` IconMode, `ExtendedSelection`,
`setSelectionRectVisible(True)`) never calls `setDragEnabled(True)`, so
`QAbstractItemView.mouseMoveEvent` drops straight into `DragSelectingState` on
any left-drag — even one that began on a valid item. Two windows were open:
(1) the 0–8 px pre-threshold moves were forwarded to `super()`; (2) after
Codex's switch from `QDrag.exec()` (nested loop, grabbed the pointer) to the
non-blocking manual drag, moves *during* the drag reach `mouseMoveEvent` with
`_drag_source_path` already cleared and also fell through to `super()`. Plus a
latent bug: `_drag_source_path` was never reset on a blank-space press, so a
stale path from a prior click could suppress the marquee.

**Fix:**
- `mouseMoveEvent`: early-return while `_manual_drag_active`; when a press
  armed a drag on an item, swallow *every* left move (start the custom drag
  past threshold) so the base class never rubber-bands on an item press.
- `mousePressEvent`: reset `_drag_source_path` / `_drag_press_pos` before
  re-arming — only an item press arms them.
- `mouseReleaseEvent`: clear the armed state on a threshold-less click.
- `_begin_manual_drag`: `setState(NoState)` up front, mirroring the native path.

Blank-space marquee is unchanged (verified by test). Wallpaper-only — gated on
`_custom_drag_enabled`.

**Tests** (`gui/test/components/test_virtual_gallery.py`, 3 new):
`test_press_on_thumbnail_then_drag_never_starts_a_marquee`,
`test_press_on_blank_space_still_marquees`,
`test_stale_drag_source_from_prior_click_does_not_block_marquee`.
`pytest gui/test/components/test_virtual_gallery.py --run-gui` → 30 passed;
`test_wallpaper_gallery` + `test_wallpaper_event_filter` + `test_wallpaper_graph`
→ 16 passed. ruff + py_compile clean. CHANGELOG left alone (churning under
other agents) — needs a `Fixed` line when it settles.

**Pre-existing (not mine):** `gui/test/core/test_wallpaper_scan_race.py` has 4
failures (`test_stop_scanner_threads_disconnects_img_scanner_signals`,
`test_settle_waits_for_gallery_workers_before_releasing_pending_switch`,
