### Claude — 2026-09-12 (live crash found+fixed: CustomFileDialog deletion; #609 resynced; PR #610 merged)

Live D12 session (user actively testing on their own machine) surfaced a real crash: wallpaper tab's directory-browse button threw `RuntimeError: Internal C++ object (CustomFileDialog) already deleted`. Root-caused two separate things:

1. **`ca681a7b`'s crash fix (schedule CustomFileDialog deletion, refcounted `gc_disabled()`) landed on `main` but never reached `milestone/gui-refactoring-roadmap`.** It predates the last main→milestone sync, so any milestone-based build (including today's D12 branches) was running the pre-fix code and hitting exactly the crash it was meant to prevent. Cherry-picked it onto milestone as PR #610 — real conflicts in `gc_safe.py` (milestone already has an equivalent refcounted guard from R1.1/#556, kept that) and `virtual_gallery_model.py` (`.signals` → `.stream` rename from R1.1, kept `.stream` + added the QueuedConnection fix). Also fixed a bug the cherry-pick itself introduced: `image_loader_worker.py`/`video_loader_worker.py` referenced nonexistent `self._is_cancelled` — real attribute is `self._cancelled`.
2. **The cherry-picked fix still crashed live**, first D12 pass. Root cause: `WA_DeleteOnClose` on a `QFileDialog` driven via `exec()` schedules a deferred delete that `exec()`'s own nested event loop processes *before* `exec()` returns — so `selectedFiles()` read a dead pointer. Removed `WA_DeleteOnClose`; the existing `finally: dialog.deleteLater()` (after the result is already read) is the correct, sufficient teardown. Retested live — clean.

PR #610 merged (`2db4876b`) after live D12 confirmation. Targeted sweep + ruff + `check_init_boundaries.py` + `check_worker_base.py` all clean throughout.

Pushed to `feature/ui-arch-23-listings-composition`, still open pending Codex re-review — not merged yet, no other blockers known.
