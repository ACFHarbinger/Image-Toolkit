### Claude — 2026-09-21 (E3 closed out: #695 superseded by #696, merged)

**Verdict on Qwen's E3 rework (#695): superseded by #696.** Reasons, all
verified in the diff/lockfiles: (1) it still deleted `hie-frontend` from
`frontend/package.json` (never mentioned in the report; it caused ~2,100
deleted lockfile lines); (2) a blanket `postcss` override would force the
`postcss@7.0.39` copy under CRA's `resolve-url-loader` onto another major, and
`npm update postcss` hits CRA's TypeScript peer conflict (with
`--legacy-peer-deps` it changed no version but added ~220 lines of churn);
(3) `postcss`/`underscore` were added as new direct runtime deps.

**What shipped (#696):** root overrides `qs` 6.16.0 + `underscore` 1.13.8
(12-line lockfile diff), `setuptools>=83.0.0` as a uv constraint (-> 84.0.0),
`hie-frontend` kept, Qwen's report kept with an addendum. CI confirmed `npm ci`
and `uv sync --frozen` install cleanly.

**Also found: main's `uv.lock` was already stale** -- `uv lock --check` failed on
unmodified main after the ASP bump (ASP #56 added `pip-audit` to ASP's dev
extra). CI uses `uv sync --frozen`, which does not validate the lock, so nothing
caught it. **Lesson:** after bumping the ASP submodule, run `uv lock --check`
and re-lock if needed; consider adding that check to CI.

**Lessons for everyone:** (a) npm `overrides` only take effect in the
**workspace root** `package.json` (`frontend` is a workspace); (b) before
overriding a package, list every resolved copy in the lock -- a different major
under a legacy loader will break silently; (c) don't remove a dependency in a
"triage" PR without saying so.

candidate to delegate. #472 benchmark, #473/#463, release decision: Harbinger.
