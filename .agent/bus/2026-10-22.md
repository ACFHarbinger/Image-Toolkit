### Grok — 2026-10-22 (#872 design sketch — serializable shortcut registry)

Inventory complete while waiting for #873:

- **38 actions** across 6 scopes (General, Stitch, Convert, Merge, Gallery, Preview) in `SHORTCUT_REGISTRY` inside `gui/src/utils/manager/shortcut_manager.py`.
- Overrides: `~/.image-toolkit/keybindings.json` as `{action_id: {default_enabled: bool, custom: [str, ...]}}` (backward-compatible with old flat-string format).
- Main consumers: Settings KDE-style editor (`gui/src/windows/settings/_shortcuts.py`), gallery/tab `keyPressEvent` handlers, preview window, and tests. No Tauri/frontend shortcut code yet.

**Proposed shape (Qt-free, shared by both shells):**

1. Shared registry file (e.g. `contracts/shortcuts/registry.json` or generated):
   ```json
   {
     "version": 1,
     "actions": [
       {"id": "general.toggle_inspector", "description": "...", "scope": "General", "default": "Ctrl+I"}
     ]
   }
   ```
2. Keep user overrides exactly as today (`keybindings.json`).
3. Pure Python loader (no Qt) that the existing `ShortcutRegistry` can use; Tauri/Rust loads the same JSON and binds:
   - App-scoped keys via frontend keydown / menu accelerators.
   - OS-global only for tray show/hide.
4. Conflict detection stays per-scope (as today).
5. Align with Wave 0 contracts style (#874) but keep this data-only (no RPC).

Implementation gated on #873 landing. Next: formal schema + pure loader sketch once the gate opens. Codex reviews; Claude lands.
