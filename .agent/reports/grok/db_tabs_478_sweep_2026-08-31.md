# Database-tab #478 crash-pattern sweep

**Date:** 2026-08-31
**Owner:** Grok
**Scope:** `gui/src/tabs/database/` — `data_browser_tab`, `scan_metadata_tab`,
`search_tab`, `entity_listings_subtab`, `database_tab`.

Looked for: JSON / large-payload load on a QThread without `@gc_disabled_run`,
`QThread.terminate()`, widgets/`QPixmap` built off the GUI thread.

## Per-tab

| Tab | Workers | Guard | terminate() | Off-thread widgets |
|---|---|---|---|---|
| `search_tab` | `SearchWorker`, `SemanticSearchWorker` | `BaseQRunnableWorker` (`#480`) | no | `QPixmap` in properties dialog is GUI-thread |
| `scan_metadata_tab` | `ImageScannerWorker`, `UpsertWorker` | Upsert `#480`; scanner was **not** guarded | no (unbounded `wait()`) | context-menu `QPixmap` is GUI-thread |
| `entity_listings_subtab` | `_SyncBackupWorker`, `ListingsSemanticSearchWorker`, `ListingsEmbeddingWorker` | backup + semantic `#480`; **embedding is torch `#481`** | no | none |
| `database_tab` | `ImageEmbeddingWorker` | **torch `#481`** | no | none |
| `data_browser_tab` | none (query/export on GUI thread) | n/a | no | none |

## Fixes this pass

- `ImageScannerWorker.run` now `@gc_disabled_run`. Scan & Tag can emit a large
  path list from a QThread (same cyclic-GC class as `#478`, even though it
  isn't JSON). Used by wallpaper too — extra coverage.
- Scan & Tag browse now passes `DIALOG_OPTS` (native-dialog class, same as
  wallpaper `#461` close-out).

## Already ticketed, not stolen

- `ImageEmbeddingWorker` / `ListingsEmbeddingWorker` — torch backfill on a
  `QThread` overriding `run()`. Explicitly `#481` Tier-2 (OpenCode). No
  `json.loads`; payload is embedding vectors.

## Not crash-class

- Data Browser `_run_query` / JSON export run on the GUI thread (possible
  freeze on a huge page, not `#478`).
- No new GitHub issue: remaining embedding workers are `#481`.
