# S-03 tray and window behaviour — go/no-go note

— Grok, 2026-10-23. Issue #889. Harbinger decides. This note is the checklist, not an OS sign-off.

## What was read

The Wave 0 tray is `frontend/src-tauri/src/tray.rs`, the role map in `frontend/src-tauri/windows/roles.json`, and `window_registry.rs`.

- Show Window and a left-click (button up) call `restore`. The menu is not shown on left click.
- Stop all cloud activity is created disabled. If it fires, it only logs that cloud stop needs the authenticated daemon path.
- Quit calls `app.exit(0)`.
- `main` and `cloud.jobs` (native label `cloud-jobs`) are webviews with `hide_on_close`. Closing `main` runs `hide_all`: hide those windows, skip the taskbar, and merge the labels that were visible into the saved set. A second hide with nothing visible keeps the earlier labels (`merge_hidden_labels`). Closing a pop-out hides that window only.
- `restore` shows the saved labels, adds `main` when it is missing, clears skip-taskbar, unminimizes, and focuses `main`.
- The `tray` role is kind `tray` and is not a hide-on-close webview. `slideshow` is kind `native`, `hide_on_close` false, and `"deferred": "#893"`. This tray does not create it.
- `window_registry.rs` tests cover the hide-on-close labels, the `cloud.jobs` / `cloud-jobs` pair, a repeated hide that keeps the pop-out, and a later hide that adds a label. They do not open a compositor.
- Nothing under `frontend/src-tauri/src` registers a global shortcut. The locked decision (global shortcuts only for tray show/hide) is not wired.
- Qt still ships Show Window, Toggle Daemon, Next Wallpaper, Quit, a balloon, a version tooltip, and an opt-in close-to-background setting (`gui/src/windows/main/_tray.py`). `collect_background_windows` hides every visible taskbar window in `WindowManager`, not only the two Tauri labels.
- The ledger has no S-03 `os_checklist`. The Qt paths stay the #873 shared rows: `gui/src/windows/main`, `window_manager.py`, `window_service.py`.

## Evidence

This machine, 2026-10-23. The Tauri shell was not launched, so no tray icon was created and no StatusNotifierItem was observed.

- `XDG_SESSION_TYPE=wayland`, `XDG_CURRENT_DESKTOP=KDE`, `WAYLAND_DISPLAY=wayland-0`, plasmashell 6.6.6.
- `qdbus6` and `qdbus` are on PATH. `qdbus-qt6` and `gnome-shell` are not.
- One KDE Wayland session. It is not a pass for KDE, GNOME, X11, Windows, or macOS.

## Recommendation

**No-go for retiring the PySide6 tray and window paths.** Keep the Wave 0 tray as the hide/restore base. Do not delete `gui/src/windows/main`, `window_manager.py`, or `window_service.py` on this note.

OS behaviour is still unmeasured, and Qt still owns the daemon toggle, next wallpaper, balloons, and the opt-in close setting. Stop-all-cloud stays disabled until the authenticated daemon path exists. The global show/hide shortcut is not registered. Harbinger runs the checklist. This machine does not tick it.

## Checklist for Harbinger

Leave every box unchecked until that run. Linux first.

### KDE Wayland

- [ ] The tray icon appears and survives a plasmashell redraw.
- [ ] Left click restores `main` and focuses it. Show Window does the same. Left click does not open the menu.
- [ ] Closing `main` hides `main` and a visible `cloud-jobs` pop-out, and both leave the taskbar.
- [ ] Closing `main` again while both are hidden, then Show Window, restores both.
- [ ] Closing only the pop-out hides that window and leaves `main` up.
- [ ] Quit exits the shell. A supervisor-owned sidecar and slideshow daemon, if they were running, keep running.
- [ ] Stop all cloud activity stays disabled and does not send a daemon command.
- [ ] The tray menu does not become a second taskbar entry.

### GNOME Wayland

- [ ] The same eight checks. Record whether the icon is an AppIndicator or missing.
- [ ] If GNOME shows no icon without an extension, record the extension. Close-to-hide still has to work.

### X11 (KDE and GNOME)

- [ ] The same eight checks with `XDG_SESSION_TYPE=x11`.
- [ ] Record whether the icon is StatusNotifierItem or XEmbed.

### Windows

- [ ] The notification-area icon restores `main` and a hidden pop-out on left click and on Show Window.
- [ ] Close hides both and skips the taskbar. A second close still restores both.
- [ ] Quit exits the shell and leaves a supervisor-started daemon running.
- [ ] A second launch focuses the running window (single-instance gate). This spike did not launch that path.

### macOS

- [ ] The menu-bar icon restores `main` and a hidden pop-out on left click and on Show Window.
- [ ] Close hides both. Quit exits the shell and leaves a supervisor-started daemon running.
- [ ] The menu does not become a second Dock icon.
