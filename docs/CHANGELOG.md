# Changelog

Notable changes to Image-Toolkit documentation, tooling, and product surfaces.

The format is based on [Keep a Changelog](https://keepachangelog.com/).

## [Unreleased]

### Removed

- **Embedded JVM cryptography module retired in favor of a native C/OpenSSL implementation** (`cryptography/cpp/itk_crypto.c` → `build/crypto/libitk_crypto.so`, built with `just build-crypto`). The Kotlin/Gradle module, the `jpype` dependency, and the `build-jar` recipes are gone; `vault_manager.py` now calls the native library through ctypes with an unchanged public API, and the JVM shutdown/`aboutToQuit` wiring in `app.py` was deleted. File formats (PKCS#12 keystore + AES-256-GCM vault) are byte-identical to what the JVM wrote, so existing account keystores/vaults migrate with zero changes — compatibility is proven by fixtures generated by the JVM module before its removal (`backend/test/data/crypto_fixture/`). This also removes the JVM/JPype native-lib conflict class implicated in the recurring gallery crash (see Addendum 31) and the Bug 1 headless-close hang.

### Fixed

- Restored `VaultManager.SecureJsonVault`, dropped when the JVM cryptography module was retired: session recovery, sync-backup export/import, and the per-file API-credential cache all construct a standalone encrypted-JSON file via `SecureJsonVault(secret_key, path)` outside the main account vault, and lost that attribute entirely (`AttributeError` on save/load) until this fix added an equivalent ctypes-backed class with the same constructor and `saveData`/`loadData` method names.
- Re-wired root `just asp-benchmark-assess` (and related ASP benchmark/triage recipes) after Anime-Stitch-Pipeline moved to `submodules/ASP`. Dispatch now calls `submodules/ASP/backend/src/cli/eval_dispatch.py` via the Image-Toolkit venv with a correct `PYTHONPATH`, avoiding broken `backend/controllers/bench_eval_dispatch.py` and bare workspace `uv run` failures on CSG’s workspace-only pyproject.
- Added compatibility shim at `backend/controllers/bench_eval_dispatch.py` for older scripts/docs.
- System-display wallpaper slideshow: countdown got stuck at `00:00` forever and wallpapers stopped rotating whenever the daemon process died without clean exit (crash, OOM, hard kill). `update_countdown()` trusted the config's stale `running: true` flag; it now reuses the PID-liveness check (`_reconcile_daemon_liveness_on_startup`) to detect a dead process, correct the config, stop the countdown timer, and reset the Start/Stop button (`gui/src/tabs/core/wallpaper_tab/system_display_subtab/_slideshow.py`).
- "Close to background tray icon" setting had no effect on a fresh launch: `MainWindow.__init__` correctly set `_minimize_to_tray` from the saved preference, then a few lines later unconditionally reset it to `False` (a stray default-init grouped next to an intentional `_tray_icon` reset for a Plasma6/Wayland workaround). Toggling the checkbox mid-session "fixed" it only because Settings' Save handler re-applies the flag directly, which the next relaunch would undo again. Moved the default-init before the preference is applied (`gui/src/windows/main/main_window.py`).
- Glassmorphic background canvas never actually showed through panels: `BackgroundConfig.glassmorphism_enabled` defaulted to `False` while the code reading it (`_theme.py`) assumed `True`, and the QSS targeted `QWidget#central_widget`/`QStackedWidget`, neither of which existed in the real widget tree — so `dark.qss`/`light.qss`'s blanket `QWidget` background rule painted every tab page opaque regardless. Flipped the default, gave `MainWindow` the `central_widget` objectName the selector expects, and added a rule for the actual tab-page container (`gui/src/styles/background_canvas.py`, `gui/src/windows/main/main_window.py`). Per-tab hardcoded panel/button colors that still override this are tracked separately (issues #450-452).

### Changed

- Moved the native crypto library from the standalone top-level `cryptography/` directory into `base/src/secret/itk_crypto.c`, so `base/` holds all of the project's C/C++ source in one place. It still builds as its own plain-C shared library (`build/crypto/libitk_crypto.so`, loaded via `ctypes`), separate from the `base` pybind11 extension — only the source location and the `just build-crypto`/CI build commands changed.

### Added

- Agent coordination for docs/website migration under `.agent/cache/AGENT_BUS.md` and `.agent/reports/grok/`.
