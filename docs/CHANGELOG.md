# Changelog

Notable changes to Image-Toolkit documentation, tooling, and product surfaces.

The format is based on [Keep a Changelog](https://keepachangelog.com/).

## [Unreleased]

### Removed

- **Embedded JVM cryptography module retired in favor of a native C/OpenSSL implementation** (`cryptography/cpp/itk_crypto.c` → `build/crypto/libitk_crypto.so`, built with `just build-crypto`). The Kotlin/Gradle module, the `jpype` dependency, and the `build-jar` recipes are gone; `vault_manager.py` now calls the native library through ctypes with an unchanged public API, and the JVM shutdown/`aboutToQuit` wiring in `app.py` was deleted. File formats (PKCS#12 keystore + AES-256-GCM vault) are byte-identical to what the JVM wrote, so existing account keystores/vaults migrate with zero changes — compatibility is proven by fixtures generated by the JVM module before its removal (`backend/test/data/crypto_fixture/`). This also removes the JVM/JPype native-lib conflict class implicated in the recurring gallery crash (see Addendum 31) and the Bug 1 headless-close hang.

### Fixed

- Gallery scrolling again uses Qt's fast opaque scroll-blit path. `OpaqueViewport` now caches a fully opaque, window-aligned composite of the configured background artwork and a theme tint instead of forcing transparent repaint propagation through the entire widget tree. This fix landed, was reverted same-day after it turned out to paint galleries pitch black whenever no background image was configured, and has now landed again correctly: the black backing came from sourcing the fill color via `self.palette().window().color()`, which never reflects the app's actual QSS-driven theme (QSS `background-color` rules don't write back into `QPalette`). The base fill now comes from the `DARK_BG`/`LIGHT_BG` theme constants instead.
- Wallpaper slideshow daemon config writes (`_sync_daemon_config`, `toggle_daemon`, `_reconcile_daemon_liveness_on_startup`, and the manual "skip" cycle) were not atomic: a plain `open(path, "w")` truncates the file immediately, then writes incrementally, so the daemon subprocess's own polling loop could read a torn/partial file mid-write and fail with `Failed to read config: Expecting value...`, silently skipping that config update — observed live, correlating with reports of the daemon "stopping" again after the earlier stuck-timer fix. Config writes now go through a temp file + atomic rename (`_write_daemon_config_atomic`) so a concurrent read always sees a complete file, never a torn one.
- Extractor background work now runs on lifecycle-owned operation pools instead of Qt's process-global pool. Video queue/extraction/scanning jobs remain separate from the gallery pool that refreshes synchronously drain, preventing cross-tab shutdown hangs and queue-completion deadlocks; the Image extractor also owns and drains its worker pool.
- Gallery thumbnail pipeline: eliminated double rendering (both `result` and `batch_result` signals were connected), removed the second `waitForDone(-1)` drain per page turn/refresh, and sized LRU caches to the active page size (500/1000/All) so thumbnails no longer evict mid-populate and re-decode. Added `LRUImageCache.resize()` for dynamic sizing. Ported the no-rescale guard to the extractor tab's card rendering (`6f31c41d`).
- LRU thumbnail caches could grow without bound: the page-size-driven `resize()` call added in the fix above sized each cache to `max(current maxsize, page size)`, which never shrinks — one directory opened with page size "All" permanently inflated the cache for the rest of the process's life, and the next large directory would inflate it further. Real-world directories (hundreds-to-thousands of images) could grow the cache into gigabytes of retained `QImage`s and swap-thrash the app into an apparent freeze. Added a hard `LRU_CACHE_CEILING` (800 entries) that bounds this auto-growth while still respecting an explicitly larger `§2.16B`-configured baseline (`gui/src/utils/cache/lru_image_cache.py`, `_loading_pipeline.py`, `_found_gallery_populate.py`, `_selected_panel.py`).
- Database tabs: stripped all hardcoded `background-color: #hex` panel styles (QListWidget, QScrollArea, QWidget containers) and re-expressed semantic action colors as theme-driven button roles (`btn_success` for add/update, `btn_danger` for delete/remove/clear). Removed inline `:checked`/`:hover` styles from format filter toggles, delegating to theme QSS (`6f31c41d`).

- Glassmorphic background canvas and Discord-style translucent panels: resolved container opacity across nested `QStackedWidget`, `QTabWidget`, `QScrollArea`, and subtab hierarchies, and stripped inline `_GROUP_BOX_STYLE` overrides in `WallpaperTab` and `MonitorDropView`. Group boxes, panels, cards, and tab panes now render with translucent alpha backgrounds (`rgba(...)`), enabling full-window background images and theme artwork to show through cleanly like Discord themes.
- Galleries, scroll viewports, and thumbnail cards: converted `MarqueeScrollArea`, `OpaqueViewport`, `ClickableLabel`, `_image_display.py`, and `_card_rendering.py` to use translucent alpha backgrounds (`rgba(...)`) instead of hardcoded `#2c2f33` / `#36393f` paints and opaque widget flags (`WA_OpaquePaintEvent`).
- Wallpaper gallery scans no longer rebuild the page twice after each image and video phase. Startup-restored monitor thumbnails are decoded at the configured thumbnail size and cached instead of loading full-resolution pixmaps on the UI thread.
- Restored `VaultManager.SecureJsonVault`, dropped when the JVM cryptography module was retired: session recovery, sync-backup export/import, and the per-file API-credential cache all construct a standalone encrypted-JSON file via `SecureJsonVault(secret_key, path)` outside the main account vault, and lost that attribute entirely (`AttributeError` on save/load) until this fix added an equivalent ctypes-backed class with the same constructor and `saveData`/`loadData` method names.
- Re-wired root `just asp-benchmark-assess` (and related ASP benchmark/triage recipes) after Anime-Stitch-Pipeline moved to `submodules/ASP`. Dispatch now calls `submodules/ASP/backend/src/cli/eval_dispatch.py` via the Image-Toolkit venv with a correct `PYTHONPATH`, avoiding broken `backend/controllers/bench_eval_dispatch.py` and bare workspace `uv run` failures on CSG’s workspace-only pyproject.
- Added compatibility shim at `backend/controllers/bench_eval_dispatch.py` for older scripts/docs.
- System-display wallpaper slideshow: countdown got stuck at `00:00` forever and wallpapers stopped rotating whenever the daemon process died without clean exit (crash, OOM, hard kill). `update_countdown()` trusted the config's stale `running: true` flag; it now reuses the PID-liveness check (`_reconcile_daemon_liveness_on_startup`) to detect a dead process, correct the config, stop the countdown timer, and reset the Start/Stop button (`gui/src/tabs/core/wallpaper_tab/system_display_subtab/_slideshow.py`).
- "Close to background tray icon" setting had no effect on a fresh launch: `MainWindow.__init__` correctly set `_minimize_to_tray` from the saved preference, then a few lines later unconditionally reset it to `False` (a stray default-init grouped next to an intentional `_tray_icon` reset for a Plasma6/Wayland workaround). Toggling the checkbox mid-session "fixed" it only because Settings' Save handler re-applies the flag directly, which the next relaunch would undo again. Moved the default-init before the preference is applied (`gui/src/windows/main/main_window.py`).
- Glassmorphic background canvas never actually showed through panels: `BackgroundConfig.glassmorphism_enabled` defaulted to `False` while the code reading it (`_theme.py`) assumed `True`, and the QSS targeted `QWidget#central_widget`/`QStackedWidget`, neither of which existed in the real widget tree — so `dark.qss`/`light.qss`'s blanket `QWidget` background rule painted every tab page opaque regardless. Flipped the default, gave `MainWindow` the `central_widget` objectName the selector expects, and added a rule for the actual tab-page container (`gui/src/styles/background_canvas.py`, `gui/src/windows/main/main_window.py`). Per-tab hardcoded panel/button colors that still override this are tracked separately (issues #450-452).

### Changed

- Promoted duplicate card rendering, styling, and preview context menu logic out of per-tab implementations into `AbstractClassTwoGalleries` (`_CardRenderingMixin`).
- Stripped hardcoded panel backgrounds and button colors across `gui/src/tabs/web/` (`DriveSyncTab`, `ImageCrawlTab`, `MediaLoaderTab`, `ReverseSearchTab`, `WebRequestsTab`, `EntityReconTab`), delegating to theme QSS and semantic button roles (`btn_success`/`btn_danger`).
- Series and entity listing galleries now render at most 100 cards per page, with previous/next navigation, instead of destroying and recreating the complete result set after every search, filter, sort, or resize.
- Core and model tabs now defer panel backgrounds to the active global/glass QSS. Success and danger actions use semantic button roles supplied by the resolved theme rather than inline green/red styles.
- Database listing-card thumbnail requests are coalesced into native batch-loader jobs with disk-cache reuse. The Scan & Tag selected-image panel now uses the shared batch-selected loader instead of synchronous full-resolution pixmap decoding.
- Moved the native crypto library from the standalone top-level `cryptography/` directory into `base/src/secret/itk_crypto.c`, so `base/` holds all of the project's C/C++ source in one place. It still builds as its own plain-C shared library (`build/crypto/libitk_crypto.so`, loaded via `ctypes`), separate from the `base` pybind11 extension — only the source location and the `just build-crypto`/CI build commands changed.

### Added

- Visual thumbnail file picker (`ThumbnailFilePicker` in `gui/src/components/dialogs/thumbnail_file_picker.py`): provides visual async thumbnail grids, directory bookmarks, size scaling, and fast single/multi-selection. Integrated with the Theme Studio / Display & Media settings for background image selection and dynamic palette extraction.
- Docs stubs: `DEVELOPMENT.md`, `SECURITY.md`, `TESTING.md`, `GLOSSARY.md`, this changelog.
- Agent coordination for docs/website migration under `.agent/cache/AGENT_BUS.md` and `.agent/reports/grok/`.
